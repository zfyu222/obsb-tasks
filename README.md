# OBSB 任务管理 0.3.9

独立 Obsidian 插件。复用 Enhancing Mindmap fork 的布局、曲线连线、选择计算和命令历史核心，不需要安装另一个导图插件。0.3.0 将数据改为可直接阅读和编辑的 Markdown 树：缩进代表父子关系，复选框代表任务状态，日期和工时采用可见属性，注释保留完整 Markdown。导图和列表读写同一份文件，旧格式可备份迁移。

## 安装与构建

推荐通过 BRAT 安装：Add Beta Plugin → 填写 `https://github.com/zfyu222/obsb-tasks` → 选择最新版本 → 安装并启用“OBSB 任务管理”。后续通过 BRAT 更新。

任务插件拥有独立仓库和版本入口；`zfyu222/OBSB` 的 BRAT 安装仍是 AI 管家，不要用它更新任务插件。

独立仓库根目录执行 `npm ci`、`npm run check`、`npm test`、`npm run build`。在 OBSB 主工程中的开发副本则先切到插件目录：

```powershell
cd plugins/obsb-tasks
npm ci
npm run check
npm test
npm run build
npm run test:bundle
```

手动安装时，把 `dist/obsb-tasks/` 内的 `main.js`、`manifest.json`、`styles.css` 放入目标 vault 的 `.obsidian/plugins/obsb-tasks/`，在社区插件中启用“OBSB 任务管理”。本次发布不自动安装或修改正式 vault。

Windows 和 Android 分别安装，沿用现有 LiveSync 同步普通 Markdown；不需要服务端进程、Node 或 Rust 运行时。移动端兼容性仍需实机验收，不能把 manifest 的 `isDesktopOnly: false` 当作验收结果。

## 使用

0.3.9：类型／层级和完成状态的非法修改在进入草稿前拦截，恢复原值并在属性栏提示，继续点击其他节点或工具栏不会重复提交同一个非法值。多选后修改“节点类型”会对全部选中节点整组校验、一次保存、一次撤销，父子节点可一起转为领域；失败整组不变，不自动改变未选中的祖先／后代。其他属性仍只编辑当前节点，未保存的名称和注释保留，实际磁盘写入失败或同步冲突仍需重试／恢复草稿。

0.3.8：去掉任务和领域文字下方的装饰横线，包括节点底边和导图核心绘制的文字基线。父子连线、优先级文字颜色、完成删除线及选中轮廓保留。

0.3.7：原位改名时输入框随草稿实时变宽／变窄，连线和子节点同步布局，保留焦点、光标及中文组合输入；不等待自动保存。编辑宽度最多 800px 并受当前缩放下的画布可视宽度约束，超长文本继续在输入框内横向滚动；退出后恢复最长 420px 的紧凑展示。布局刷新合并到动画帧，不额外写文件。

0.3.6：直接点击任务名称前的 `○` 标记已完成，自动填写完成时间并显示灰色删除线；点击 `✓` 恢复待办并清空完成时间。支持撤销／重做。有未完成子任务的父任务会提示先处理子任务；领域没有此按钮，归档视图只读。按钮获得焦点时 Enter／Space 切换状态，名称仍负责选中、改名和拖动；改名时点击圆圈会先保存名称，再完成任务。

命令面板运行“OBSB 任务管理：打开任务管理”，或点击侧边的树形列表图标。插件启用时不创建文件，首次打开管理面板才建立 `Raw/任务管理/当前任务.md`。

- 顶部“+ 任务”和“+ 领域”立即创建默认节点，直接挂 root，不再弹出表单；选择节点后可加子任务／子领域。
- 导图中选中节点：`Tab` 添加子任务，`Enter` 添加同类型的同级节点（插在当前节点之后）。选中 root 时两者都直接添加 root 下的任务。新任务默认待办、重要程度中、无截止日期和计划日期、工作量 0；不复制原节点的状态和注释。
- 新增后自动选中节点名称，输入名称按 `Enter` 确认，再按一次 `Enter` 可添加同级；名称输入时按 `Tab` 会先保存名称再添加子任务。`Space`、`F2` 或双击节点可改名，`Escape` 取消本次名称修改，不删除已创建的节点。
- 0.3.4 原位改名时，点击其他节点／画布空白或失焦到右侧属性栏会先保存，再关闭名称输入框。切换节点保持目标选择，空白处取消选择，属性栏保留输入焦点；保存失败保留原编辑器与草稿，修正后可重试。输入法组合输入结束后再提交；Tab 创建子任务的新输入框不会被旧编辑器的失焦事件关闭。
- 选中节点后，右侧“节点属性”可直接编辑名称、任务／领域类型、状态、重要程度、日期、工作量、完成时间、标签、父节点和 Markdown 注释。下拉选项改变、文本字段离开输入框时自动保存，不用另开弹窗或点保存；父节点搜索最多列出 100 个候选。
- 任务与领域可互换，保留 ID、注释、链接及原任务属性（领域状态下隐藏任务属性）。按整组修改后的层级校验：任务下禁止领域；验证失败恢复原类型，不自动搬家或修改未选中节点，其他草稿仍保留且可继续导航。
- 领域可嵌套领域；任务下禁止领域，所有节点单父节点并禁止循环。
- 任务状态为待办、进行中、等待中、已完成、已取消；重要程度高／中／低；支持日期 deadline、计划日期、预计／实际小时、完成时间和标签。
- 在右侧状态栏选“已完成”即可完成任务；节点留在当前文件，导图、列表、搜索默认仍包含它。有未完成后代的父任务不能标记完成；不会自动完成父任务。
- 完成时间使用日期时间选择器，按本机时区显示和编辑；标记已完成时自动填写，也可修改。Markdown 仍保存标准 ISO 时间，已有数据无需迁移。
- 注释支持原生 Obsidian Markdown 预览；编辑是原始 Markdown 文本框，不承诺第三方插件扩展语法或嵌入式 Live Preview。
- “切换列表”平铺所有任务；可搜索名称、注释、标签，按状态筛选，按截止日期或重要程度排序。
- 画布采用真正的双侧导图布局，也可切换“向右展开”；标题宽度、分支间距和曲线由提取的核心计算。小图首次自动适应视口，大图保持可见区渲染，可用“聚焦”只看一个领域／任务子树。
- 0.3.1 导图改用紧凑单行节点：高 24px、宽度随名称变化，最长 420px 后省略，悬停可看完整名称及状态／截止日期；移除第二行属性文字、领域卡片外框，缩短分支间距。高／中／低优先级分别以红／橙／蓝文字和底线表示，完成／取消显示灰色删除线；右侧属性修改会即时更新颜色，深色主题使用较亮配色。详细属性仍在右栏，列表保持原有信息。
- 0.3.2 领域名称移除方框前缀，使用主题的柔和灰色和常规字重，宽度相应缩短；任务保留状态标记和优先级颜色。
- 0.3.3 参考 Enhancing Mindmap 的分支圆点：移除方形加减按钮，改为沿连线的 12px 小圆点；展开为实心、收起为空心，悬停稍放大，可点击或键盘激活。叶子无圆点，聚焦子树同样可以折叠，双击圆点不会进入改名；折叠仅影响当前视图，不改任务文件。
- 右键拖动画布；也可点抓手按钮，用左键平移。普通滚轮／触控板平移，Ctrl/Cmd＋滚轮以鼠标所在位置缩放；工具栏可缩放、居中、适应画布。触摸提供单指平移和双指捏合，Android 手感仍待实机确认。
- 左键空白处拖出框选，Ctrl/Cmd/Shift 点击可追加／切换多选。拖动节点到目标中部作为子节点，目标上／下部调整同级顺序；父子同时选中时只移动顶层根。领域不能拖到任务下，也不能拖进自己的子树。
- 0.3.5 鼠标拖动有跟随指针的半透明节点影像，原节点淡化；目标中间显示“放入”轮廓，上下边缘显示同级插入线，并显示目标文字提示。非法目标显示原因，松手不会移动；Esc、失焦、丢失指针捕获或画布外松手可取消。预览不写数据，松手后一次提交、一次撤销；多选最多复制 5 个预览节点并显示分支数量，子树整体移动。触摸仍沿用画布平移／捏合，暂不新增触摸节点拖动。
- 方向键切换节点，Home 回到中心。Delete／Backspace 删除所选子树；Ctrl/Cmd+Z 撤销，Ctrl/Cmd+Y 或 Ctrl/Cmd+Shift+Z 重做。创建、名称编辑、属性和拖放使用同一运行期历史，空白处取消选择后仍可撤销。右侧输入框保留自身文字编辑行为。
- 归档、休眠和批次恢复是跨文件操作，不加入上述撤销栈；使用对应恢复入口。刷新、切换数据入口或重新打开视图会清空运行期命令历史。尚不包含跨图子树剪贴板与精确历史回放。
- 快捷键只作用于当前导图，搜索、属性输入框及注释中的 Tab／Enter 不会触发建节点；IME 选词和长按键重复不触发新增。归档／历史视图保持只读。
- 切换节点、切换视图或归档前会先保存待写入属性；外部修改冲突会阻止覆盖并保留草稿，可在右栏复制或确认放弃后重新加载。若关闭视图时保存失败，会保存本机副本，命令面板“查看未保存的节点草稿”可找回；此副本不参与 LiveSync，也不自动覆盖服务器内容。

## 全局归档与领域休眠

“全局归档已完成”预览数量后，将所有已完成且后代均完成的任务移入独立归档批次。保留领域和未完成任务；跳过仍有未完成后代的已完成父项，但可以归档其中已完成的叶子分支。取消任务不自动归档。

“空领域”仅列出没有任何当前任务的领域，供逐个选择休眠；不自动判断领域过期。领域内仍有未完成任务时拒绝休眠。允许将领域及其已完成后代一起休眠，也可先归档完成任务再休眠空领域。

“休眠领域”中选中领域后可恢复该批次和必要祖先，保留 ID、注释和文档引用；不恢复此前单独归档的任务。“任务归档”也支持恢复整个批次，恢复的任务仍是完成状态。若必要祖先已不存在，会从批次上下文恢复，界面确认会说明这一点。

恢复不删除归档文件；插件按节点 ID 去重，当前已存在的节点不覆盖。日常当前视图、统计和搜索只用当前文件，进入归档／休眠／回顾才读取对应目录。

### 原生搜索的必要设置

插件内搜索已经默认排除归档和休眠。Obsidian 原生全库搜索不自动遵守插件过滤，需在每个设备的“设置 → 文件与链接 → 排除文件”中添加：

- `Raw/任务管理/归档/`
- `Raw/任务管理/休眠领域/`
- `Raw/任务管理/归档事务.md`
- `Raw/任务管理/格式备份/`

插件不擅自更改客户端设置。本项目 `knowledge-qa` 已加入对应的日常检索排除规则；明确历史问题或显式节点链接可以访问归档。原生搜索设置尚未在真实客户端验证，安装后需检查同名任务归档前后是否消失；专门历史入口不依赖原生搜索。

## 时间回顾与笔记引用

“时间回顾”显式查询当前、归档和休眠数据，按本机时区的创建或完成日筛选，日期范围两端包含。列表只列命中任务；导图补充祖先为虚线上下文。

这不是逐日状态回放：当前节点优先，其余采用最近归档记录，不能还原某天修改前的标题、deadline 或父子关系。首版不记录每次操作事件，未来精确回放只能从历史记录机制启用后开始。

节点注释直接使用 `[[普通文档]]` 等 Obsidian 语法。普通文档引用节点时，使用详情中的“复制稳定链接”，得到带 vault 名和节点 ID 的 `obsidian://obsb-task` Markdown 链接；归档后显式打开仍会定位对应归档。原生 `[[当前任务#^节点ID]]` 不具备归档重定位能力，首版不对全库链接做替换。

## 数据格式与写入边界

```text
Raw/任务管理/
├─ 当前任务.md
├─ 归档事务.md                 # 首次归档时创建，保存一个待完成事务指针
├─ 归档/<时间>-<批次ID>.md
├─ 休眠领域/<时间>-<批次ID>.md
└─ 格式备份/旧格式-<SHA256>.md  # 迁移前原文，不参与当前或历史查询
```

### Markdown 树格式（人工与 AI 编辑约定）

文件保留 frontmatter 和一行 `obsb-file` 系统信息；`format: 2` 表示树格式，内部模型版本仍为 1。下面是正文示例，节点系统信息可由插件补全：

```markdown
- 领域：AAA 项目 ^n-project
  - [ ] 完成注册系统开发 ^n-register
    [重要程度:: 高]
    [截止日期:: 2026-11-10]
    [预计工作量:: 480 分钟]
    [标签:: ["后端", "AAA"]]
    > 参考 [[注册系统需求]]。
    >
    > - 注释里的列表仍属于注释。
    - [x] 完成需求确认 ^n-requirements
      [完成时间:: 2026-10-27T18:30:00+08:00]
    - [ ] 完成前端开发 ^n-frontend
- [ ] 整理本周工作记录 ^n-weekly
```

- 每层使用两个空格，必须从顶层开始，不能跳级；缩进是父子关系的唯一来源，不再保存 `parent`。同层顺序就是导图顺序。普通 `- 领域：名称` 表示领域，带复选框的列表项表示任务；任务下面不能挂领域。
- 状态映射：`[ ]` 待办、`[/]` 进行中、`[?]` 等待中、`[x]` 已完成、`[-]` 已取消。原生 Markdown 对自定义复选框的外观取决于客户端／主题，插件按上述语义读取。
- 行末 `^n-...` 是稳定 ID，保留已有 ID；新增时指定文件内唯一的 ID，如 `^n-register-backend`，字符限字母、数字和短横线。不要复制已有 ID，也不要通过改 ID 表示改名。标题里的 Markdown 标点由插件转义，AI 编辑时保留转义规则。
- 属性和注释比节点多缩进一级。属性一行一个：`重要程度`（高／中／低）、`截止日期`、`计划日期`、`预计工作量`、`实际工作量`、`完成时间`、`标签`。日期为 `YYYY-MM-DD`；工作量支持 `8h`、`8 小时`、`120 分钟`、`120min`，插件统一输出分钟以保留精度。标签为 JSON 字符串数组；完成时间建议写带时区的 ISO 时间。
- 缺省属性为重要程度中、无日期、工时 0、空标签。新增节点可省略系统注释，由插件在保存时补全创建／更新时间；手工勾选完成且未填完成时间时，插件读取时补记时间，随后保存。原生编辑器重新打开任务时，同时清除完成时间属性；插件内切换状态会自动清除。
- 每行注释使用 `> ` 前缀，空行写 `>`；该层引用仅作为注释边界，读取时剥去一层。注释自己的 Callout／引用再加一层 `>`，代码块、表格和任务列表也逐行放在注释引用内。不要把注释列表直接当作结构列表缩进，否则它会被当成子节点。
- 每节点通常有一条短 `obsb-meta` 注释，只保存创建／更新时间、可选的扩展属性和领域转换前的状态。不要删除或改写已有系统信息。名称、层级、任务状态与日常属性均以可见 Markdown 为准；未知扩展字段保留在 `extra`，不丢弃。
- 归档文件也使用同样的树。`[归档上下文:: 是]` 表示仅为理解和恢复而附带的祖先，不属于该批次实际归档任务；不要修改此标记或批次系统信息。默认检索排除归档、休眠、事务和格式备份。历史查询也不包含格式备份。

AI 可直接在同一份 Markdown 中添加节点、改名、移动整个子树、更新属性与注释。修改后需用插件重新加载校验；格式损坏、重复 ID／属性、未知属性、非法层级或未加引用前缀的正文会阻止写入，原文保留，不静默修复。

### 旧格式迁移与恢复

升级后，旧版二级标题＋`obsb-node`／`obsb-end` 文件继续可读，仅打开不会改写；第一次正常保存或归档更新旧文件时，先保存逐字节原文备份，再写树格式。需要一次转换当前、归档和休眠文件时，运行命令“OBSB 任务管理：迁移任务文件为可读 Markdown（先备份）”。命令先保存视图草稿，再逐个校验、备份和转换；任务 ID、属性、注释、同级顺序、归档上下文和批次状态保持一致，不生成第二份可编辑事实源。格式备份不参与插件默认搜索和历史查询。

备份失败或源文件被其他设备改动时停止覆盖；多文件迁移不是整体事务，失败前已经转换的文件和备份会保留，修正问题后可重复运行，已转换文件跳过。恢复旧格式时，先关闭任务视图并完成同步，核对对应备份再以原路径替换正文；不要把备份和当前文件一起导入任务。旧版插件不能读取树格式，所有设备应更新到 0.3.0 后再迁移。迁移不会由本次开发自动作用于正式 vault。

所有生成文档标记 `nightly_maintenance: skip`，沿用现有完整整理的排除机制。数据为 Raw 下的普通 Markdown，进入现有 Git、LiveSync 和备份范围。没有隐藏数据库或唯一缓存。不要把任务文件当普通笔记拆分、合并或移动；整篇文件的结构操作仍走 `tools/vault_ops.py`。插件的归档是编辑节点内容及新增批次文件，不直接移动或删除任何笔记文件。

写入采用当前文件 SHA-256 快照与 `Vault.process()` 的内容比较，过期表单、已到达的外部编辑会被拒绝，不静默覆盖；尚未同步的远端并发仍由 LiveSync 保留冲突处理。归档前建议各端先完成同步。

归档顺序为：写 prepared 副本 → 保存事务指针 → 比较并更新当前文件 → 标记批次 committed → 清空事务指针。重启仅检查事务指向的一个批次，不扫描全部历史。未执行源写入的 prepared 副本保留但不展示；源移出成功后可自动补记提交。无法判断的跨设备中断会停止写入并保留所有文件，需人工检查。不得直接删副本来“修复”。

## 性能与验证

## Git 与 BRAT 发布维护

开发主源位于 OBSB 工作区的 `plugins/obsb-tasks/`，独立仓库 [zfyu222/obsb-tasks](https://github.com/zfyu222/obsb-tasks) 保存完整源码和可独立构建的发行镜像。框架文件、vault、运行数据和秘密不导出。

1. 在主源修改插件，同时更新 `package.json`、lockfile、`manifest.json`、`versions.json` 和 `release-notes.md`；运行检查、测试、构建及 `test:bundle` 后提交。
2. 运行 `node scripts/export-release.mjs <独立镜像目录绝对路径>`。首次目标目录必须为空，后续必须是带有镜像标记的干净 Git 工作区。脚本只复制白名单源码，并仅清理上次清单拥有的过时文件。
3. 在发行镜像提交并推送，再推送与 manifest 相同的 tag，如 `0.1.0`，不加 `v`。独立仓库的 `.github/workflows/release.yml` 会构建并上传 `main.js`、`manifest.json`、`styles.css` 三个未压缩附件。
4. 等待工作流完成，核验 Release 的版本和三个附件。只推送 Git 提交不会让 BRAT 自动获得新版，必须发布 Release。

构建强制检查 manifest、package 和版本兼容表一致。发行工作流位于独立仓库根部；主工程嵌套的同一文件不会替代现有 AI 管家工作流。尚未选择项目开源许可证或申请官方社区目录，公开发行不自动代表这些事项已完成。
